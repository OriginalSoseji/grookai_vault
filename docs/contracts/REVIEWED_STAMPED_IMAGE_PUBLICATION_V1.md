## Static registered stages

The registered `reviewed_stamped_image_publication_v1` recipe has exactly four
ordered, implemented stages:

1. Verify the frozen source, current review decisions, full original candidate,
   evidence, classification, parent/child, registry and truth-review state,
   reviewed trigger definitions, schema/security frame and protected references.
2. Copy the 33 already card-plane originals to their fixed content-addressed
   derived paths in private `user-card-images`, without overwrite. Fully decode
   and hash the originals, read back every derived object and recheck originals.
3. Exercise all 33 real warehouse approvals, stages and shared image executions
   inside a SERIALIZABLE transaction, then roll back and verify the complete
   original state independently.
4. Require that successful rehearsal under one hour old, apply all 33 images in
   one SERIALIZABLE transaction, then independently verify database receipts,
   immutable Storage bytes and the public canonical image responses.

Task data cannot supply SQL, shell commands, worker paths, environments or
arbitrary endpoints. The source-bound scope supplies every canonical target,
original and derived path. The public check uses the fixed canonical website
route; only its same-path HTTPS canonical-domain redirect is admitted. Service
credentials and private evidence links are never sent to that public route.
Transient public read failures may receive at most three read attempts. Missing,
contradictory or transformed image bytes are not repaired by a retry or new apply.

required environment counts. Independent audit sessions use read-only database

## Durable outcome and uncertainty

A warehouse receipt committed in the same transaction retains the original
state, source/plan/actual-command linkage, atomic plan and receipt, and the exact
after-state fingerprint. Independent readback checks all records and the shared
atomic receipt. Repeated receipt verification is read-only.

The source repository and its Actions artifacts are public. Runner artifacts and
errors contain only allowlisted failure codes, counters and fingerprints. Never
upload full review packages, original/private image bytes, candidate snapshots,
raw assertion diffs, error causes or proposed receipt bodies to Actions artifacts.
Complete receipts remain in the private warehouse and retained operator evidence.
If public verification or artifact persistence fails after an acknowledged commit
or independent receipt confirmation, the failure must retain the known committed
state. It must not report zero committed changes or reapply the images.

An unknown COMMIT acknowledgement never causes another apply. A fresh independent
session may recognize the exact durable receipt and continue verification. If
there is no matching receipt, stop without retrying a canonical write. A lost
rollback acknowledgement may be reconciled only when the complete rehearsal
receipt exists in retained attempt evidence and independent reads prove the
original state exactly. An incomplete rehearsal cannot become rollback proof.

Ambiguous Storage upload responses are followed only by exact object readback,
not a second upload. A matching immutable object may be accepted; absent or
different bytes stop the workflow. Never delete or overwrite a contradictory
object to force a release. Keep failures, proposals, laboratories and evidence.

## Qualification boundary

The local harness creates separately owned copies of the retained synthetic
PostgreSQL17 template. It uses one synthetic account, zero copied real accounts,
sessions or collections, and no production credentials or HTTP access.
Historical template PL/pgSQL bodies use CRLF. Construction installs the already
reviewed exact production function bytes in the new fixture, and the unchanged
strict comparison must then pass. It never edits the retained template,
normalizes a comparison, rewrites a migration or waives a gate.

Required cases include actual immutable Storage copy/replay, full 33-image
rollback, wrong authority, original-row and review-note drift, unknown triggers,
competing writers, SQL failure after earlier images changed, receipt failure,
lost actual COMMIT/ROLLBACK acknowledgements, absent commit receipts, exact
independent after/replay and zero-write rejection of a consumed apply. Whole
fixture relation and sequence snapshots must show only the four allowed domain
tables changed by a committed image apply. Local proof is not production closure.
