# Pokemon World2010 Master integration V1

Standing repair-owner authorization covers this additive local source integration
of 92 qualified existing-parent identities across four World2010 decks. All 17
held source IDs and reasons remain unresolved. No finish admission, production
write, release, mapping execution or human signature is provided by this tool.

The integration independently replays the original relationship review, four
checklists, identity projection and frozen membership profiles against the current
Master. It updates four base artifacts: cards, sets, source availability and index.
It appends eight source-availability rows, 184 evidence records in aggregate counts,
and six evidence files (four originals, public TCGCSV warehouse rows and a manifest).
It preserves historical summary fields and preparation metadata, all prior arrays,
all existing printings and every prior completion result. Source identity stays
TCGCSV. The immutable manifest binds each admitted fact to its original evidence.
Existing canonical/review snapshots remain private external qualification inputs.

The CLI `scripts/audits/pokemon_world2010_master_integration_v1.mjs` requires the
exact repair worktree, cwd and branch. It accepts only these argument sets:

- `--mode=integrate --journal=<new directory> --snapshot=<file> --receipt=<file>
  --review=<file> --originals-dir=<directory>` prepares and integrates local source.
- `--mode=reconcile --journal=<directory> --out-file=<new file>` independently
  classifies every intended write as before, after or unknown without mutating Master.
- `--mode=resume --journal=<directory> --recovery-receipt=<file>` requires an exact
  independent mixed/all-after readback before completing a known interrupted write.

The journal retains exact baseline copies of all nine base artifacts, frozen after
bytes, hashes of every input and a complete recursive inventory of the active
Master. Existing output directories, occupied scope, path escapes, symlinks,
changed inputs, changed protected bytes and unaccounted files fail closed.
Recovery also replays original semantics and revalidates the independent observation;
a changed payload with a recomputed self hash cannot replace source evidence.

Each executor acquires its exclusive `.world2010-master-integration.lock` with
PID and journal metadata. Source files use exclusive adjacent temporary files,
fsync and rename. The ten-file change is not a filesystem-wide transaction.
Process death may retain a lock or temporary file: inspect its identified process,
all journal hashes and temporary bytes before any separate recovery disposition.
This version deliberately refuses unknown bytes, unexpected temporary files and
occupied locks; it never deletes a stale lock or overwrites unknown data itself.
An all-after lost acknowledgement can write a terminal receipt without rewriting
source files. An already completed journal refuses another integration.

Qualification covers full copied-Master preservation, duplicate admission,
mixed/all-after recovery, changed inputs/backups/outputs, held membership,
source-path confinement and lock exclusion. After source integration, rebuild the
ordinary completion artifacts, independently verify publication remains blocked,
freeze source and run unchanged repository hooks before normal commit/push.
Every external checkpoint distinguishes source integration from repaired database
relationships. New 83-raw ingress retaining nine lineages, the 92-relationship
executor/journal, actual SQL/application qualification and production readback
remain separate; historical printing/ME05 applies must not be replayed.
