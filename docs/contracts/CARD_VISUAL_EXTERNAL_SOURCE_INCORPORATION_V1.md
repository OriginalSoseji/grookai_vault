# Card Visual External Source Incorporation V1

Status: ACTIVE SOURCE-GOVERNANCE CONTRACT; NO NETWORK IMPORT AUTHORIZED

## Purpose

External visual-search projects can accelerate Grookai without causing another
OpenAI Vision run. They may contribute collector vocabulary, query demand,
candidate card relationships, and review priorities. They do not become
canonical identity or active visual truth merely because another site displays
the claim.

No site is scraped into active search.

## Governing Pipeline

```text
registered source
-> permitted snapshot, export, API, or manual research lane
-> immutable source manifest and raw record hash
-> exact canonical card-print reconciliation
-> candidate staging
-> image-based role confirmation
-> founder/admin confirmation
-> immutable visual-search assertion release
-> collector-facing search
```

A source taxonomy is not Grookai ontology. Every imported label is translated
into a candidate and resolved against Grookai's evidence roles.

## Source Lanes

### RotomAmiti Cameo Database

Current use: candidate import from the operator-supplied spreadsheet snapshot.

The existing importer preserves source rows, hashes, notes, formatting, and
canonical reconciliation. Imported rows remain role-unresolved unless explicit
source detail and image review prove the role. This is the only researched
source currently authorized for row-level snapshot processing.

### SightDex

Public scope: community identification of featured Pokemon, cameos, and
Pokemon shown as objects.

Current use:

- collector-query demand;
- role vocabulary;
- candidate-source and partnership planning.

Future permitted export:

- `featured` may propose `scene_subject`;
- `cameo` remains role-unresolved until the image distinguishes a physical
  subject, reflection, depiction, or other case;
- `object` remains role-unresolved because SightDex groups plushes, statues,
  logos, posters, screens, and balloons while Grookai separates depicted
  subjects from character representations.

Community consensus can prioritize review. It does not bypass image
confirmation.

### Artchu

Public scope: visual discovery tags across scenes, styles, moods, actions,
objects, artists, and sets.

Current use:

- controlled-vocabulary research;
- collector-query evaluation;
- UX and filter coverage analysis.

Future permitted export must split:

- objective scene/object/action tags into observation candidates;
- style and mood labels into optional semantic-concept candidates;
- Pokemon cameo tags into role-unresolved appearance candidates.

Card-level tags are not copied without written permission or an approved
export/API agreement.

### TCG Curator

Public scope: community-built tags for themes, objects, locations, food,
Pokemon appearances, artists, and binder discovery.

Current use:

- controlled-vocabulary research;
- source-backed collector queries;
- product behavior and correction-workflow research.

Future permitted exports remain candidate evidence. Community votes affect
review priority, not evidence authority. Subjective tags never become observable
facts.

### BinderBloom

Public scope: color-oriented binder arrangement and connected panoramic-art
detection.

Current use:

- product behavior and query-demand research;
- panorama and visual-cohesion vocabulary.

Future panorama data requires a separate artwork-relationship candidate
contract. It must not be forced into `scene_subject`, `depicted_subject`, or
`character_representation`.

### ArtFinderTCG

Current use: natural-language artwork-search benchmark and collector-query
research only.

No card-level result, tag, or ranking data is imported.

## Licensing And Access

Every source requires a registry record before an adapter can exist. The record
must state:

- source owner and homepage;
- acquisition mode;
- permission status;
- permitted use modes;
- terms or permission evidence;
- terms snapshot hash and review date when applicable;
- network and snapshot-import permissions;
- authority ceiling;
- source-specific taxonomy mapping.

Unknown or unverified reuse rights mean:

- no automated crawl;
- no hidden API use;
- no bulk data copy;
- no card-level import;
- no active-search authority.

The preferred route is direct outreach for a stable export, API, or partnership
agreement. Grookai should offer attribution, source links, refresh cadence,
correction exchange, and reciprocal coverage reports.

## Candidate Authority

External records enter `card_visual_evidence_candidates` with:

- source registry ID;
- source URL and source record ID;
- raw payload and SHA-256;
- licensing provenance;
- exact canonical reconciliation status;
- proposed identity and appearance role;
- host object or surface when explicitly supplied;
- source image hash when available.

Exact canonical reconciliation proves which card the source refers to. It does
not prove that the source's visual claim is true.

Only these authorities can enter an immutable search release:

- observation-backed Fact Graph evidence;
- human image-confirmed evidence;
- explicitly role-confirmed external evidence permitted by source rights.

## Review Strategy

Use external-source agreement to reduce labor:

1. Prioritize candidates supported by multiple independent sources.
2. Show the self-hosted Grookai image, not a copied source image.
3. Ask the reviewer only for identity, role, host, and visibility confirmation.
4. Preserve PokeJavi decisions as drafts.
5. Require founder/admin confirmation for promotion.
6. Publish assertions in the next immutable release, never directly into the
   active release.

Disagreement creates a review queue. Absence from a source never deletes an
existing assertion.

## No-Repayment Rule

Existing Fact Graphs remain immutable. External sources enrich candidate
coverage beside them. Missing cameo, representation, panorama, or vocabulary
coverage is repaired through deterministic reprojection and targeted human
review, not a broad paid Vision rerun.
