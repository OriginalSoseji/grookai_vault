# Pokemon World2010 atomic relationship execution V1

This new automated policy and local-only executor binds all 92 qualified
existing-parent relationships. It preserves 17 explicit holds, 109 original
parent UUIDs/GV-IDs, 100 child printings/reviews, 13 historical printing raw
receipts, the full 2,001-product source group and 77 retained raw/discovery pairs.
TCGCSV remains TCGCSV with `tcgcsv:2282:product` external IDs. No finish, parent,
set, image or source-product mutation is authorized.

The offline stager requires seven explicit directories: projection, baseline,
ingress, SQL observation, active Master, review and a new immutable output.
It replays original deck evidence against the preserved pre-integration Master,
compares every active Master identity and requires two equal read-only verified
TLS observations with actual SQL identity hashes and zero collisions. It creates
a fresh UUID intent and before/package/completion receipts. Embedded observations
are qualification inputs; they do not grant continuing production authority.

One SERIALIZABLE transaction inserts 83 raw/discovery pairs, 92 identities,
184 source-evidence rows, 92 exact mappings and two bound ingestion-job journals:
536 inserts across six tables, no updates or deletes. The inner ingress journal
and outer relationship journal commit atomically. A standalone ingress journal
cannot be adopted as a completed canonical transaction. All nine selected retained
lineages keep their original IDs and payloads. Mapping metadata binds raw ID,
discovery ID, identity ID, active Master key and source/review fingerprints.

Discovery rows retain their original review state and payloads; the existing
warehouse coverage reader derives exact relationships from the new mappings.
This deliberately avoids rewriting historical review assertions. All 17 held
products remain unresolved. The executor cannot silently resolve a held product,
substitute a numeric TCGplayer mapping or infer finish truth.

The executor requires a server-reported loopback address and a newly created
`grookai_world2010_subset_canonical_*` lab. It acquires the hourly discovery,
group, subset and its own execution locks. Local table fences exclude source,
parent, child and mapping phantoms; row checks preserve retained content.
These broad fences are qualification scaffolding, not a production latency or
locking guarantee. The executor never commits; its caller owns the transaction.

Readback binds complete identity/evidence/mapping row fingerprints, exact decimal
mapping/raw IDs and both ledger IDs. Missing, partial, conflicting, changed or
replacement rows reject reconciliation. After a lost commit response, a second
connection must compare the full readback with the immutable pending receipt
before further action. Exact complete repeats insert nothing. A missing outer
journal with committed inner rows is an error, never permission to retry.

The SQL proof clones the actual selected public/Auth schema and translated owner,
retaining all older fixture rows. Only the four unreferenced namespace stubs and
source-sync fixture are materialized from fresh production READ ONLY capture
before the new baseline. New target columns, constraints, indexes and triggers
are compared to live definitions. A separate sentinel exercises inbound edges.
This is PostgreSQL16 proof with empty Auth users, not PostgreSQL17, real Auth,
application/public search or all inbound-schema/performance qualification.

Production remains disabled. Required next gates: catalog-bound outside
dependency preservation (including nonempty generated mapping-ID lookup), bounded
production lock/runtime qualification, frozen producer/active-Master binding,
normal committed/pushed source, a new governed production CLI and fresh sanity,
collision, apply, independent canonical/printing/mapping and public-search proof.
Do not remove the local guard, replay historical World/ME05 packages, repeat
completed active Master integration or reuse an old intent as production approval.
