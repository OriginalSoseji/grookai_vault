# Reviewed stamped image preparation V1

Status: read-only preparation component. Its pure functions create no production
apply or publication authority. The separately gated
[publication composition](REVIEWED_STAMPED_IMAGE_PUBLICATION_V1.md) is under qualification.

This component consumes the founder's existing manual visual reviews under
[the manual approval workflow](FOUNDER_MANUAL_APPROVAL_WORKFLOW_CONTRACT_V1.md).
It prepares the original 33 League-stamped Reverse images for the existing
warehouse pipeline. It does not repeat visual questions, require model credit,
approve warehouse candidates, create staging, or publish images.

## Shared exact-image interpretation

`existing_child_image_interpreter_v1.mjs` serves both backend preparation and the
web warehouse interpreter. An exact classified existing-child image repair is
considered before generic new-stamp identity handling. It requires matching
resolver, audit and resolution targets, finish, name, number, set and audited
parent variant. A null variant in finish-only routing means no parent-variant
creation; a non-null conflicting variant blocks this interpretation.

The result proposes only ENRICH_CARD_PRINTING_IMAGE. It does not change the
classifier, infer a new parent, clear holds, or replace the staging write plan.
Unresolved stamp identities and existing NO_OP precedence retain their prior
interpretations. HIGH interpreter confidence describes deterministic target
agreement, not a machine estimate of image quality or extraction confidence.

## Byte-preserving card-plane assets

`reviewed_card_plane_asset_v1.mjs` implements a source-independent asset method
within [promotion normalization](PROMOTION_IMAGE_NORMALIZATION_V1.md). It applies
only when a retained operator technical assessment confirms an upright, complete
card-plane front, without surrounding background, with stamp, number and set
evidence intact. That assessment is distinct from the founder's identity review.

The method verifies the private evidence reference, original SHA256, byte size,
actual JPEG format, orientation, dimensions, and complete decode. It copies the
bytes unchanged. No crop, warp, resize, repaint, sharpening, inferred detail,
model call or manufactured resolution is allowed. Images needing a pixel
transform remain outside this method.

Offline results are PREPARED, not READY normalization packages. The eventual
derived object must use the existing private `user-card-images` bucket and
content-addressed `warehouse-derived/self-hosted-images-v1/reviewed-card-plane-v1/`
prefix, already supported by web and native canonical image consumers. Original
evidence remains immutable. Upload must prohibit overwrite. Exact pre-existing
objects may be reused only after full byte readback.

Finalization requires a separate readback of the exact derived object and
revalidates the prepared plan and original bytes. Only then may it produce the
standard READY promotion-normalization package, with original and derived hashes
equal and machine confidence null. This pure finalizer does not upload, persist
an event, approve a candidate, stage a write, or confer publication authority.

Do not upgrade the 31 original review-only tasks into executable tasks. Do not
publish a task with an unimplemented handler. A genuine approved publication
outcome may cover all normal internal stages without serial founder checkpoints.
Normal source, hosted, release and production verification gates remain binding.
