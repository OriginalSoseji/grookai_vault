# Pricing Completion Source Export V1

The fixed read-only source exporter enumerates **every non-publish qualification decision in one reconciled published production pricing run**, across all six recognized repair lanes. It replaces the identity-only import limitation for that precisely bounded population. It does not claim all warehouse products were selected, invent expected source subtypes for products without price observations, or enumerate Master Index printings.

## Components

- `backend/pricing/pricing_completion_source_export_v1.mjs`: `readPricingCompletionSourceSnapshotV1(client, { now, maxAgeMs?, expectedRunId?, maxRows? })` owns a repeatable-read/read-only transaction, verifies those transaction settings, queries fixed SQL with parameters, and requires acknowledged rollback. It returns `{snapshot, normalized, receipt}`. `snapshot` follows `PRICING_COMPLETION_INPUT_V1`; `normalized` is the corresponding validated intake result.
- `pricingCompletionReadOnlyDatabaseConfigV1(url, { ca?, insecureTlsEnvironment? })` produces a dedicated configuration with `default_transaction_read_only=on`, verified remote TLS, connection/query timeouts and no URL query overrides. It reads no environment and initializes no database connection.
- `scripts/audits/pricing_completion_source_export_v1.mjs`: fixed CLI using only `PRICING_COMPLETION_READONLY_DB_URL` and optional `PRICING_COMPLETION_DATABASE_CA_PEM`. It imports no dotenv file and logs no environment values or raw PostgreSQL errors. Use a dedicated least-privileged read-only database account; the variable name and transaction mode are not substitutes for actual account permissions.

The CLI requires a new absolute `--out-dir=`; its parent must exist. It writes exclusively created `snapshot.json`, `receipt.json`, `master_coverage.json`, `artifact_hashes.json` and `input_manifest.json`. The latter uses the worker's `PRICING_COMPLETION_SNAPSHOT_FILES_V1` digest-bound input schema. Optional `--expected-run-id=` binds a selected pipeline run; otherwise it selects the latest published/verified, reconciled production run. Optional `--max-rows=` defaults to 250,000 and cannot exceed 1,000,000. Exceeding the bound fails; it never silently truncates or marks a partial page complete. No apply mode exists.

The CLI also runs the fixed `readPricingCompletionMasterSnapshotV1` and `buildPricingCompletionMasterGapExportV1` modules inside the **same transaction before rollback**, explicitly scoped to Pokemon and USD. Source-run gaps retain their actual provider category, including Magic; the Master census is Pokemon-only and must never be reported as all-game Master coverage. The master artifact preserves unpriced exact printings, usable exact market quotes and parents without child printings. Parent-only gaps cannot receive fictional exact-printing queue IDs.

The source reader's optional `readMasterSnapshot(client, { sourceRunId, capturedAt, sourceObservedAt })` hook exists only for this fixed reviewed integration. It accepts an imported trusted function, never a module path, command or SQL from worker input. The combined envelope uses capture time while source coverage and per-row evidence retain source finish time. Any failed master census aborts acceptance of the entire combined export. Without the hook, Master coverage remains unknown.

Before the Master callback, the exporter independently reads the application's valid current publication context and requires its run ID and publication-set ID to match the selected source run. A shared transaction alone cannot establish this relationship because an explicitly selected historical run may differ from the current pointer. Missing, ambiguous or mismatched context fails before the Master RPC. `publicationBinding` with both IDs and an evidence digest is retained in the receipt, combined snapshot and each observation; the callback also receives this binding.

## SQL and reconciliation

The transaction reads `market_price_pipeline_runs`, the corresponding `tcgcsv_source_sync_runs`, all qualification decision counts and an independent publication snapshot count. The selected run must have a completed, failure-free current-full source sync. It reads every non-publish decision ordered by decision UUID, with a parameterized hard limit of the configured bound plus one. LEFT JOINs to source observations, products and groups preserve orphaned evidence instead of silently dropping rows.

Run totals must exactly match ledger counts and actual snapshot count. Publish/eligible counts must agree; all selected decisions must partition into publish/exclude/quarantine/delay/suppress-stale. The exported rows must exactly match the non-publish total and its decision partitions. Every row maps to one recognized primary reason/lane; unknown reasons fail the whole export for explicit policy review. Stable duplicate source identities, duplicate decision/observation UUIDs, provenance mismatches and conflicting currencies fail closed.

Source category, product, subtype and currency must be present. When the source observation exists, its product ID, exact subtype, source-price-row identity and currency must match the qualification decision. Conflicting coordinates fail the whole export instead of routing another card's evidence into a repair. Missing warehouse metadata is retained as evidence flags if identity dimensions remain provable; inability to identify a row fails the export rather than pretending it was repaired. Publication run IDs and source sync IDs remain distinct evidence fields.

## Condition, freshness and completeness

The approved target is the application's existing TCGPlayer Market price, not a price for every physical condition. The warehouse schema `20260715110000_tcgcsv_full_source_warehouse_v1.sql` and application publication/read model define market price and currency but do not supply a physical condition. The fixed exporter therefore uses the scope sentinel `condition:"NOT_CONDITION_SPECIFIC"`, with `evidence.priceBasis:"TCGPLAYER_MARKET"` and `physicalConditionVerified:false`. This states the market-price basis without asserting NM or a condition-adjusted price. A queue verifier must require the same price basis and exact identity in an independently verified application readback before closing the item. Legacy identity-only imports remain `UNKNOWN`; this change does not rewrite or relabel their evidence.

Source sync finish time controls source coverage freshness; a new audit capture or recent publication timestamp cannot freshen old source evidence. Default intake freshness is 24 hours. Source coverage is complete **only for the frozen pricing-run decision census**, with exact counts for all six lanes. Master-side coverage is unknown for source-only API calls; combined Pokemon census coverage is evaluated for the explicit TCGPlayer Market basis and remains partial when parent-without-printing gaps remain. Physical condition coverage is separately unverified and is not the selected completion target. Receipt scope and source denominator must accompany any dashboard or automation claim; zero selected-run source gaps alone never establishes all-card completeness.

To establish all-card completeness, separately enumerate warehouse products absent from the pricing run and exact Master Index printing/currency/condition requirements, including canonical parents lacking printing identities. Preserve those gaps as unresolved; do not fabricate printing IDs or treat excluded products as completed work.

## Trust and validation

Run the fixed reviewed exporter in a separately deployed read-only service. Never execute worker-supplied code, SQL, repository hooks or dependencies with host/production credentials. This source-only implementation neither configures that deployment nor establishes production role permissions. Hash manifests bind output content; they do not authenticate the producer.

Contract tests use a strict in-memory SQL-client fixture in the isolated runner. They cover all six lanes, orphan preservation, fresh/stale evidence, parameter binding, transaction mode, rollback acknowledgement, counts/limits, duplicates, unknown reasons, TLS configuration and unknown Master coverage. No live database access or migration belongs to the test. Successful fixture tests are not a production query-plan or permission proof.
