# Pokemon Classic frozen package and execution journal V1

Status: exact source binding and isolated receipt qualification. No production
apply entrypoint or production approval is enabled.

The standing repair-owner task authorizes this automated policy. Reviews retain
actual automated attribution and the original reviewed_at timestamp. A fresh
production observation cannot rewrite reviewed source bytes. The frozen loader
replays all102 originals against the three checked-in manifests, exact review
bytes, Master projection and the active Master cards/printings/profiles. Its
fingerprint includes every bound file. Observation time and source-review time
are separate. Jumbo remains unresolved outside the standard English deck scope.

Producer capture streams the complete binary Git diff into SHA256. It never
truncates output to fit a buffer and never exports diff contents. Failure of Git
fails the capture. Public/Auth relation and function owners, schema grants,
role attributes and memberships, and default ACLs join the schema fingerprint;
these are evidence bindings, not proof of a complete Auth/application replay.

The new execution journal qualifies the existing ingestion_jobs table; it adds
no schema and creates no pending work for another worker. A succeeded receipt
and all102 canonical relationships plus21 ingress lineages belong to the SAME
serializable transaction. The receipt binds a new execution UUID, exact canonical
and ingress fingerprints, frozen package fingerprint, every parent and new
discovery UUID, and exact per-table counts. An advisory lock specific to this
protocol prevents competing attempts. Existing own/shared writer locks remain.
The original local-host and proof-database guard remains in force.

A transaction-validation result is not a commit receipt. The caller preserves
an immutable pending artifact before COMMIT and never reports success merely
because COMMIT was sent. Lost responses are resolved through an independent
repeatable-read READ ONLY connection. A matching ledger AND exact canonical,
printing, mapping, raw and retained-lineage readback prove committed state.
A ledger without exact data, exact data without a ledger, duplicate ledger rows,
a changed execution UUID or changed payload stops reconciliation. Fully absent
state is recorded without automatically retrying. Failure handling never
rewrites an unknown succeeded receipt as failed. Fresh qualification is required
before a separately authorized retry; no consumed historical package is reused.

The SQL qualification uses a new named database cloned from the prior isolated
fixture. Only that NEW clone is reset to its exact pre-Classic scope; original
labs remain unchanged. It qualifies rollback, failure after canonical insertion,
receipt rejection, ledger tampering, duplicate receipts, own-lock concurrency,
commit, lost-response reconciliation and zero-write repeat. Fixture dependencies
remain partial, so these results cannot substitute for actual isolated
Supabase/Auth/HTTP and complete application ownership/RLS qualification.

Production still requires the new governed production CLI, final committed and
normally qualified producer, complete dependencies/Auth/HTTP, image admission,
fresh target/TLS/count/schema/source/absence checks and bounded locks. No boolean
in a JSON artifact removes these gates. Image pointers, pricing, family promotion,
provider finish mapping and the healthy hourly worker remain separate.
The subsequent `POKEMON_CLASSIC_DEPENDENCY_REPLAY_V1.md` adds actual selected
dependency/owner replay and exact additive transaction-statistics assertions.
Its optional proof input expands local qualification only; runtime and production
gates above remain intact.
