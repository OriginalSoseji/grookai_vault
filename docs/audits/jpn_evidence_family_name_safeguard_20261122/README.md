# Japanese evidence name safeguard — November 22, 2026

An active source-evidence row can retain English candidates from an older identity. Previously those names were copied into current existing-parent candidates and used to infer species for unrelated candidates. The safeguard permits an evidence name in those two paths only when the row is active, linked to the one active identity, and its normalized name appears in that identity's English candidates. Missing, ambiguous, different or malformed identity anchors fail closed. Evidence rows and IDs remain in the audit baseline; this change does not retire or alter them.

In a bounded read-only simulation of 92 current DP4 parents with no fresh source assertions or family links, the guard retained all 184 active evidence IDs, excluded all former names and yielded no current names from those stale rows. This is not a full admission, writer, provenance or source-equivalence proof. `dp4-simulation.json` pins the policy bytes used.

An aggregate production snapshot found 109,214 active Japanese evidence rows whose nonempty name arrays were contained exactly in their unique current identity's array. Another 264 rows had at least one nonidentical raw name, and 230 lacked a unique active identity. These are structural counts and an upper bound on names removed: normalization can make nonidentical strings equivalent, and card counts overlap. They do not prove that an excluded name is false or authorize changing evidence. See `jpn-exact-upper-bound.json` and `jpn-structure.json`.

The separate inactive-evidence master-index and adjudication safeguards are prerequisites. Active source records still carry the prior assertions, source-specific correction remains unimplemented, and other consumers may require changes. This candidate does not make the catalog or resolver launch-ready. The scoped candidate/admission/provenance tests cover stale, missing, ambiguous, wrong-identity and matching-name cases, and the unaffected review/promotion suites.
